# 快速开始（5 分钟跑起来）

> 本文档面向**第一次接触本 Harness** 的工程师，目标：5 分钟内熟悉目录结构，并跑起一个空骨架。

---

## 1. 看图认路（30 秒）

```
Harness_Engineering/
├── .claude/Claude.md               ← AI 红线总章（必读）
├── .harness/
│   ├── rules/                      ← 项目硬规则（4 份）
│   ├── skills/                     ← AI 工作流技能（7 份）
│   ├── agents/                     ← AI 角色（4 份）
│   ├── wiki/                       ← 静态知识库（架构 / 数据 / 接口 / 术语 / 模板）
│   └── changes/                    ← 每次变更留痕
├── docs/                           ← 本目录
├── src/                            ← （未来）业务代码
├── tests/                          ← （未来）测试
├── pyproject.toml                  ← Python 项目元数据
├── .python-version                 ← 3.11.9
├── .env.example                    ← 环境变量模板
└── README.md                       ← 项目门户
```

---

## 2. 准备本地环境（3 分钟）

### 前置依赖
- Python 3.11+
- uv 包管理（`pip install uv`）
- Docker Desktop（用于集成测试）

### 安装依赖

```bash
cd D:\Project\Harness_Engineering

# 创建虚拟环境（uv 自动）
uv sync --all-extras

# 复制 env
cp .env.example .env
# 编辑 .env，至少填上 OPENAI_API_KEY
```

> **当前 Harness 仅是约束环境，**业务代码 src/ 尚未生成。所以这一步只是装好 lint/type/test 工具。

---

## 3. 本地开发 checklist（2 分钟）

```bash
# 1. lint
uv run ruff check .
uv run ruff format --check .

# 2. 类型检查
uv run mypy src/

# 3. 红线扫描
uv run python scripts/check_red_lines.py   # 后续实现

# 4. 跑现有测试（PoC 暂无业务代码，主要验证脚手架）
uv run pytest -q
```

任何一项失败 = 不能 commit。

---

## 4. 第一次提交流程

1. **读 `.claude/Claude.md`**（AI 红线 16 条）
2. **选角色**：`.harness/agents/` 4 选 1（Owner / Planner / Coder / Reviewer）
3. **走 10 阶段流水线**（见 `.harness/rules/开发流程规范.md`）
4. **变更留痕**：在 `.harness/changes/{YYYYMMDD}-{feat}/` 复制 `.harness/changes/templates/summary.template.md` 起一份
5. **CI**：push 后自动跑 lint / type / test / coverage

## 6. 常见问题

### Q：本项目可以直接跑业务代码吗？
**A**：当前 Harness **只是约束环境**。具体业务项目应在 `src/ai_agent/` 下开发（参见 `.harness/rules/工程结构规范.md`）。

### Q：Alembic / 数据库连不上？
**A**：本项目默认使用 PostgreSQL + pgvector。集成测试时建议：
```bash
docker run -d --name pgvector -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres \
  pgvector/pgvector:pg16
```

### Q：LLM API 调用失败？
**A**：检查 `.env` 中 `OPENAI_API_KEY` 是否填写正确；CI 默认无 key 也能跑（mock）。

### Q：如何新增一个 AI 红线？
**A**：修改以下 3 处（必须 Owner 决策）：
1. `.claude/Claude.md` R 区
2. `.harness/rules/ai-special-rules.md` 细则
3. `scripts/check_red_lines.py` 检测规则
