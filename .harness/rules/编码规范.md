## 2. 后端规范

### 2.1 异步与并发

- 所有 I/O 密集函数声明 `async def`，**禁止**在 async 函数内同步阻塞调用（文件 / DB / HTTP / LLM API 阻塞超过 100ms）
- CPU 密集型用 `asyncio.to_thread()` 或 `ProcessPoolExecutor`
- 并发多个独立 IO → `asyncio.gather(..., return_exceptions=True)`，**禁止**顺序 await
- WebSocket / SSE 处理必须支持断开信号（`asyncio.CancelledError` 必须正常 cleanup）

```python
# ✅ 正确
async def fetch_documents(ids: list[str]) -> list[Document]:
    return await asyncio.gather(*(get_by_id(i) for i in ids))

# ❌ 错误（循环等待）
async def fetch_documents(ids):
    out = []
    for i in ids:
        out.append(await get_by_id(i))
    return out
```

### 2.2 异常处理

- **必须**使用自定义异常体系（`.exception.*`），禁止向外泄露原始异常
- 自定义异常层级：

```python
BaseException
└── HarnessException
    ├── BusinessException          # 业务错误（参数 / 权限 / 状态）
    │   ├── ParameterException
    │   ├── AuthException
    │   └── ResourceNotFoundException
    ├── AIException                # LLM / Agent / Tool 错误
    │   ├── LLMTimeoutException
    │   ├── LLMParseException
    │   ├── ToolExecutionException
    │   └── AgentBudgetExhaustedException
    └── InfraException             # DB / Redis / 第三方异常
        ├── DatabaseException
        └── CacheException
```

- `api/` 层由 `exception/handler.py` 统一捕获，**返回 `{code, message, data}`** 三段式结构
- 禁止 `except Exception: pass`

```python
# ✅ 正确
try:
    result = await llm.ainvoke(prompt)
except LLMTimeoutException:
    logger.warning("llm.timeout", model=settings.model)
    raise

# ❌ 错误
try:
    result = await llm.ainvoke(prompt)
except Exception:
    pass
```

### 2.3 日志（强制使用 structlog）

- 任何模块级必须 `import structlog`，定义模块 logger：`logger = structlog.get_logger(__name__)`
- 日志 key 名使用 `snake_case` 风格：`request_id`, `user_id`, `conversation_id`, `latency_ms`, `token_usage`
- 禁止 `print()` 代替日志
- PII / 敏感字段必须先经 `guardrail.pii.redact()` 再记日志

```python
logger.info(
    "llm.call.completed",
    model=settings.llm_model,
    prompt_tokens=resp.usage.prompt_tokens,
    completion_tokens=resp.usage.completion_tokens,
    latency_ms=round((time.perf_counter() - start) * 1000, 2),
    request_id=request_id,
)
```

### 2.4 配置管理

- 使用 `pydantic-settings`，**单一** `Settings` 实例（`config/settings.py`）
- 禁止任何 `os.getenv(...)` 调用散落业务代码
- 多环境切换：`APP_ENV=staging` 加载 `.env.staging`

### 2.5 数据访问（repository 层）

- 全部使用 SQLAlchemy 2.0 async 风格
- 复杂查询放 `repository/{table}_repo.py`
- 业务逻辑**严禁** import `sqlalchemy.*`
- 跨多表的事务在 `service/` 层用 `async with session.begin()` 控制

```python
# ✅ 正确
async def create_conversation(user_id: str) -> Conversation:
    async with uow.transaction():
        conv = await conversation_repo.create(user_id=user_id)
        await message_repo.create(conv.id, role="system", content="...")
        return conv
```

### 2.6 重试 / 熔断 / 限流

- 所有外部调用必须套用 `.infra.retry.with_retry()`（指数退避，默认 3 次）
- LLM / Vector DB 必须套用熔断器（`pybreaker.CircuitBreaker`）
- 用户级别限流用 `slowapi`（`@limiter.limit("60/minute")`）

### 2.7 幂等性

- 所有工具函数 **必须**接受 `idempotency_key: str | None = None`
- 写操作的 service 层 **必须**支持幂等（基于 `idempotency_key` + Redis setnx）

## 3. LLM / Agent 相关规范

### 3.1 LLM 调用

- **禁止**直接 `ChatOpenAI().invoke()` 散落在业务代码
- **必须**通过 `llm/factory.py` 工厂 + 统一包装（自动注入 timeout / retry / token 计数 / tracing）
- **必须**显式设置 `model`, `temperature`, `max_tokens`, `timeout`

```python
# ✅ 正确
from ai_agent.llm.factory import get_llm
from ai_agent.guardrail.token_counter import TokenCounter

async def summarize(text: str, request_id: str) -> str:
    llm = get_llm(model="gpt-4o-mini", temperature=0.0, timeout=30)
    counter = TokenCounter()
    with counter.track(request_id=request_id, model="gpt-4o-mini"):
        resp = await llm.ainvoke(prompt_template.format(text=text))
    return resp.content
```

### 3.2 Prompt 管理

- **必须**用 YAML 文件 + `PromptLoader` 加载
- 版本号必填（`v1`, `v2` …）
- 业务代码只引用模板名，不直接写字面量

```yaml
# prompts/chat_system_v1.yaml
name: chat_system_v1
version: 1
template: |
  你是 {{ agent_name }}，一个专业的{{ domain }}助手。
  用户当前语言是 {{ user_language }}。
  请基于以下知识回答：
  {% for chunk in context_chunks %}
  - {{ chunk.content }}
  {% endfor %}
variables:
  - agent_name
  - domain
  - user_language
  - context_chunks
```

### 3.3 Agent 工具

- 所有工具继承 `tool.base.BaseTool`
- 必须实现 `name` / `description` / `args_schema`（Pydantic）/ `_run` / `_arun`
- 必须实现 `idempotency_key(self, **kwargs) -> str`
- 涉及**对外副作用**（发邮件 / 删除 / 写外部系统）的工具必须在 LangGraph `interrupt` 处挂起等 HITL 审批

```python
from pydantic import BaseModel, Field

class SearchKBInput(BaseModel):
    query: str = Field(..., description="搜索关键词")
    top_k: int = Field(default=5, ge=1, le=20)

class SearchKBTool(BaseTool):
    name = "search_knowledge_base"
    description = "在指定知识库中检索相关文档片段"
    args_schema = SearchKBInput

    async def _arun(self, query: str, top_k: int = 5, **_) -> list[dict]:
        return await self.kb_service.search(query=query, top_k=top_k)
```

### 3.4 RAG 规范

- 文档切分使用 token-aware splitter（按 tiktoken 计数）
- 召回必须**多路融合**（向量 + BM25），至少 topK=20
- 重排序**必须**用 rerank 模型（bge-reranker / cohere rerank），**不能**少
- 引用必须回传到 LLM 的 prompt（`source_documents` 字段）
- Embedding 维度必须与建表时一致（默认 `text-embedding-3-small` = 1536）

### 3.5 Token 用量与配额

- 每次 LLM 调用结束**必须**写入 `usage_logs` 表
- `guardrail.token_counter` 维护当日配额
- 超过 80% → 报警；100% → 拒绝服务（抛 `AgentBudgetExhaustedException`）

## 4. 安全规范

### 4.1 密钥管理

- **禁止**任何形式的 API Key / 数据库密码硬编码
- **必须**从 `pydantic-settings` + 环境变量加载
- `.env` 文件**必须** `.gitignore`
- 生产环境用 Vault / AWS Secret Manager / 阿里云 KMS

### 4.2 注入防御

- 所有 SQL 操作使用 SQLAlchemy 参数化（`session.execute(select(ORM).where(...))`）
- **禁止** `f"... WHERE id='{user_input}'"` 这种字符串拼接
- Prompt 拼接 **必须** 用 `PromptTemplate.format(**vars)`，**禁止** `f"...{user_input}..."`

### 4.3 PII 防护

- 用户输入先经 `guardrail.pii.redact()` 后再进 Prompt
- 日志记录前再过一次 `redact()`
- 审计日志保留脱敏后的原文 + 原始哈希（合规取证）

### 4.4 提示词注入防御

- 检索回来的 chunk 必须与系统指令物理隔离（独立变量、显式标注 "以下为参考资料"）
- 对外工具返回值必须经过 `output_filter.strip_injection_marks()` 再入 Prompt

## 5. 测试规范

- 测试文件命名 `test_*.py`
- 测试函数命名 `test_<行为>_<条件>_<期望>`（例：`test_chat_when_no_kb_should_use_general_prompt`）
- 一个测试函数一个断言焦点
- LLM 调用**必须**使用 `respx` 拦截，禁止打真实 API
- 集成测试需要真实 DB / Redis（docker-compose up 后跑）
